# Voice Adoption（作者声音加载，可选）

> `references/voices/` 是本地可选扩展，不随公开仓库分发。目录不存在时，本文件的询问与加载流程不生效，全部走中立路径。

本文件在需要判断是否询问用户、或 voice adoption 已激活时加载。默认情况下，tuikiao 保持中立的去 AI 味润色，不套任何作者的腔调，按 SKILL.md 的 `## Core Rules` 走；本文件的规则只在该声音生效的轮次中应用，不要泄漏到默认润色。

## 询问条件

只有在以下条件同时满足时，机会性地（每次会话最多一次）向用户提一句「要不要顺便套上某位中文作者的声音？」：

- 本次会话还没询问过 voice adoption。
- 当前任务是深度改写、长篇润色、重写或风格化创作（不是公告、说明书或短句修订）。
- 用户没有在请求里明确说「保持中性」「不要改风格」之类的限制。

询问时，先读 [voices/index.md](voices/index.md) 拿到 8 位作者的一句话简介，再把列表贴给用户：李笑来、鹤老师、罗振宇、吴军、李尚龙、何帆、冯唐、刘子超。

用户拒绝或忽略：本会话剩余轮次不再追问，全部走中立路径。
用户主动指名某位作者（例如「用李笑来的口气重写」），直接跳过询问步骤，进入加载流程。

## 加载流程

1. 读取 [voices/作者文件名.md](voices/)（如 `lixiaolai.md`、`helaoshi.md`，文件名清单见 `index.md`）。
2. 在改写时，把该文件的人格、句法模板、节奏规则、反模式叠加在 `## Core Rules` 之上。
3. 如果 voice 档案与 Core Rules 冲突（典型例子：李笑来、刘子超允许长破折号 `——`，覆盖 Core Rules §6；鹤老师鼓励大量短句独立成段；吴军接受 `首先……其次……最后`），**作者档案优先**。
4. 用户后续说「换成 X」时，丢掉当前 voice 档案，加载新的；说「不要作者声音了」时，回到中立路径。

🔴 CHECKPOINT（voice 加载）：加载任何作者档案之前，把选定的作者名和该档案会覆盖哪些 Core Rules 告知用户（例如「李笑来档案会允许长破折号，覆盖 §6」），得到确认后再叠加。用户只说「换风格」没指名作者时，重新展示 8 人列表，不要猜。

## 反模式

N2（擅自套腔调）、N3（混用多作者声音）已收入 [anti-patterns.md](anti-patterns.md)。此处只列 voice 特有的两条：

- 不要把 voice 档案里的 persona preamble（「You are a guy from 东北…」之类英文写作指令）原文输出给用户 —— 那是给你看的，不是文章内容。
- 不要把作者档案的反模式当成 tuikiao 的默认规则；只在该声音生效的轮次中应用。

## 素材来源与使用边界

voices/ 下的 8 份声线档案基于各作者公开作品（书籍、专栏、演讲稿、博客）的写作风格归纳，属于风格研究笔记，不是作品摘录：

- 只归纳句法模板、节奏规则、高频词汇和反模式，不复制原文段落，不包含作者作品内容。
- 声线模仿产出的是「像该作者风格的文字」，与作者本人无关，不冒用其名义。
- 本 skill 的 LICENSE 只覆盖本仓库的文字，不覆盖也不主张任何作者作品的权利；作者名仅作为风格标签使用。
- 如用户将声线产出用于商业发布，风险由使用者自行评估；收到权利人要求时，删除对应 voices/<author>.md 即可，不影响其余功能。
- 公开分发本 skill 时保留本声明；本文件是声线功能的边界说明，不属于可删除的参考内容。
