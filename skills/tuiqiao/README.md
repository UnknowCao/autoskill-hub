## 它解决什么问题

事情是这样的：你让模型写了一篇中文稿，读起来每个字都认识，但就是不对味。句子一样长，段落一样齐，「不仅……更是……」连着用，结尾还要拔高一句时代宣言。

一般的「去 AI 味」提示词救不了这个。它们要么只有五条原则，要么是把英文检测清单翻译了一遍——英文的 AI 痕迹（em dash、-ing 分词、三段式法则）和中文的痕迹不是一回事。中文的 AI 味长在别的地方：翻译腔、「不是……而是……」的机械对照、三项凑数、同义词轮换、句尾的分词拔高，还有「」和 "" 混用这种排版病。

推敲（tuiqiao）把中文母语编辑的语感拆成了 22 类可查的模式，每类都有修改前/修改后样例；改完还有一张 5 维评分表（直接性/节奏/信任度/真实性/精炼度，总分 50，45 分达标）——**改得行不行，不用凭感觉，用分数说话**。

## 效果示例

**轻改**（真实 benchmark 案例 01）：

> 输入：在当今这个快速发展的时代，AI 不仅改变了我们的工作方式，更是重塑了整个行业的格局。对于企业来说，要想在激烈的市场竞争中立于不败之地，就必须拥抱这一变革。值得注意的是，数据不再是简单的资源，而是新的生产要素。这标志着智能时代的到来。
>
> 改写：AI 正在改变公司的工作方式，行业的竞争格局被重新洗了一遍。企业跟不上，就会掉队。最实际的信号是：数据开始像机器和厂房一样参与生产，成了新的生产要素。

**重写**（案例 02，拆结构腔）：

> 输入：标题：为什么你的团队需要 DevOps。首先，DevOps 是一种文化。其次，DevOps 带来效率提升：它可以打通部门墙，使得协作得以顺畅展开。最后，DevOps 是未来的趋势。综上所述，拥抱 DevOps，就是拥抱未来。
>
> 改写：DevOps 是一种文化，但更实际的变化是：部门之间的墙被打通，协作不再靠来回交接。开发和运维进了同一条流程，协作顺畅了，效率也上来了。这才是团队该考虑它的原因，而不是因为它顶着未来趋势的标签。

**排版专项**（案例 13，引号统一/破折号/英文空格/日期）：

> 输入：该方案于2026年2月26日上线——LLM（大语言模型）会处理 coworkers / agents 之间的关系。
>
> 改写：该方案在 2026 年 2 月 26 日上线。LLM（大语言模型）负责处理 coworkers/agents 之间的关系。

完整 15 条对抗样例（含评分与弱项说明）见 [examples/benchmark/cases.md](examples/benchmark/cases.md)。

## 快速开始

```bash
npx skills add UnknowCao/autoskill-hub/tuiqiao
```

没有发布到注册表之前，也可以直接复制目录安装：

```bash
cp -r tuiqiao ~/.claude/skills/     # Claude Code
# 其他 runtime 装到各自的 skills 目录即可，SKILL.md 不绑定任何单一 runtime
```

装完对 Agent 说：

```text
帮我把这段去一下 AI 味，改得像中文母语者写的：<粘贴文本>
```

## 触发方式

- 「帮我把这段去一下 AI 味」
- 「这段读起来像 AI 写的，帮我推敲一下」
- 「润色成中文母语表达」
- 「改得像博客或书里写的」
- 「减少翻译腔」
- 「这段的 AI 味重吗？重的话帮我改，改完按你的评分维度打个分」
- 「用李笑来的口气重写这篇」← 声线是本地扩展（档案自备，不随仓库公开），加载前先确认
- 「把这段改成普通话，别带翻译腔」

不要用于：英文文本、代码或配置文件。（公告、说明文会被保守处理，不重写立场与口径。）

## 能做什么 / 它会交付什么

| 能力 | 交付物 |
|---|---|
| 去 AI 味改写（轻改/重写两档，3 段以上先报力度再动笔） | 改写后全文 + 3–6 个最明显问题点 |
| 按需双版本 | 「轻改版」+「重写版」各一份 |
| 改写质量评分 | 5 维评分表（直接性/节奏/信任度/真实性/精炼度，总分 50），每维附原文证据 |
| 作者声线（可选，档案自备） | 声线加载框架内置；`references/voices/` 自备作者档案（本地扩展，不随仓库公开） |
| 排版专项 | 引号样式统一（"" 或 「」 全篇二选一）、破折号清除、英文术语空格、日期格式 |

## 它和同类有什么不同

| 维度 | 常见同类（英文检测清单翻译版） | 推敲 |
|---|---|---|
| 模式来源 | 维基百科英文「Signs of AI writing」直译，检测 em dash、-ing 分词等英文痕迹 | 22 类中文母语模式，全部带修改前/修改后样例 |
| 母语参照 | 无 | corpus：王小波、阮一峰、刘瑜、柴静等，按文体选参照 |
| 排版规则 | 不覆盖 | 「」/"" 裁决、半角空格、`coworkers/agents`、`2026 年 2 月 26 日` |
| 可验收性 | 无 | 5 维评分 + 45 分达标线 + 反例黑名单 N1–N6 |
| 失败处理 | 无 | F1–F6：无文本、短文、引号冲突、判断强度失控都有兜底路径 |
| 声线框架 | 无 | 声线加载框架（档案自备），加载前告知会覆盖哪些规则 |
| 自测资产 | 少数有 benchmark | 15 条对抗样例 + `python scripts/backtest.py` 全量回归 |

同类项目（respect）：[op7418/humanizer-zh](https://github.com/op7418/Humanizer-zh)（英文清单翻译的先行者，skills.sh 上 4.4 万安装）、[shuorenhua](https://github.com/MrGeDiao/shuorenhua)（103 条 benchmark 的评测工程）、[qu-ai-wei](https://github.com/LifelongLazyLearner/qu-ai-wei)（结构级重写与敏感信息门检）。推敲不与它们抢"检测项更多"，只做它们没做的那件事：**中文母语的语感，做成可执行知识库**。

## 安全边界

- **不补事实**：原文没有的数字、人名、机构、事件，一律不编；只能补"无实体、无数字"的通用机制，且必须标注「此处按行业常识补了机制，发布前请核实」。
- **不擅自动判断**：原文的绝对化结论（如「赢者通吃」）会被压低强度，但改动会点明；用户要求保留则原样保留。
- **不擅自套腔调**：作者声线只在用户确认后加载，一次只套一位，加载前告知会覆盖哪些规则。
- **不发起外部请求**：纯本地规则库，不调 API、不读网络。
- **引语不动**：引用内容只统一标点，不改写。
- **停下来问**：3 段以上未说明力度时先报力度等确认；引号样式无法裁决时给两种示例请用户指定。

## 验证与测试

```bash
python scripts/backtest.py examples/benchmark/cases.md
```

期望输出：`总计 15 例，PASS 15，FAIL 0`，退出码 0。脚本会检查每条改写：禁用痕迹是否清除、是否残留破折号/表情符号、引号是否混用、评分加总是否与总分一致、总分是否低于 35（低于 35 应打回重写）。该脚本已做反向验证（植入违例必报 FAIL）。

一条验收 prompt：`这段文字的 AI 味重吗？帮我去完 AI 味之后，按你的评分维度打个分。`——合格表现：先答"重不重"，改写后给出 5 维分数、每维一句原文证据，总分 ≥45 直接交付、35–44 附弱项说明、<35 打回重写。
