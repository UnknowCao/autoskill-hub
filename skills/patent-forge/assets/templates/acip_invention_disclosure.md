# ACIP (华进) 技术交底书模板 — 软硬结合案

> **来源**: ACIP 华进知识产权（一家合作专利第三方公司）
> **适用类型**: 发明和实用新型技术交底资料（软硬结合案件）
> **本质**: 发明人 → 专利代理师的技术交底材料（非最终专利申请文件）
> **参考原文**: `1.6 电子-软硬结合类-发明和实用新型技术交底资料提纲2020 15.doc`

---

## 撰写须知（原文摘录）

在撰写技术交底资料之前请仔细阅读以下说明：

1. 一份好的技术交底资料会节省后续大量的沟通时间，也会提高专利申请文件的撰写质量；
2. **专利法保护的是具体的技术方案，而非单纯的功能和作用**，因此交底书中请尽量要给出实现某种功能或者达到某种目的的具体方案；
3. **专利法对于"公开充分"有明确的要求**，为了后续授权阶段专利的稳定性以及维权时权利有足够的解释空间，技术交底资料要尽可能详细，**可将专利代理师作为研发新人看待**；
4. **专利法对于"清楚"有明确的要求**，在技术交底资料中对于同一个被描述对象要用同一个词语来表述，不能出现前后不一致的情形；
5. **软硬结合案件同时包括对硬件结构和控制方法的改进**，基于改进的结构提供新的控制方案。例如，由传感器、控制器和驱动器组成的设备驱动系统，控制器根据传感器采集的参数进行分析判断，结合判断结果控制驱动器对设备进行驱动控制。
   - 软硬结合案件的技术交底书中可结合**硬件结构图**和**控制流程图**来进行描述；
   - 为了便于高效地沟通，**不能仅有图而没有文字描述，必须有对应图的文字描述**；
6. 您提供的附图专利代理师在使用时会进行适应性处理，为了提高效率，请您尽量**提供可编辑的图档**，例如使用 visio 绘制的电路图，请提供 `.vsd` 格式的原图文件；
7. 专利撰写过程中会存在较多技术沟通，为了确保专利的撰写质量并能按期完成，如果专利代理师请您补充必要的技术资料，请您及时补充。

## 输出结构（严格按此顺序，共 9 节）

### 表头 — 专利申请技术交底资料表

| 字段 | 内容 | 说明 |
|------|------|------|
| **专利申请案件名称** | 一种应用于 [应用领域] 的 [核心装置/方法] | 发明名称，开头用"一种..."，体现技术领域+核心创新 |
| **发明人** | [姓名，多人用顿号分隔] | 必填 |
| **申请人** | [公司/机构全称] | 必填 |
| **技术问题联系人** | [姓名] | 必填，便于代理师沟通 |
| **技术问题联系人电话** | [手机/座机] | 必填 |
| **技术问题联系人邮箱** | [邮箱] | 必填 |
| **已公开或即将公开发表与本技术相关的资料**（期刊、论文、宣传册等） | [ ] 是 [ ] 否 | 影响新颖性判断，需如实勾选 |

### 一、背景技术

#### 1.1 介绍本技术方案所处的技术领域、背景以及相关技术发展

撰写要求：
- 开头一句话点明技术领域（"本发明涉及 XXX 技术领域，特别涉及一种 YYY"）
- 概述该技术领域的发展现状与应用场景（让代理师快速进入语境）
- 描述现有技术路线与主流方案的演进
- 引出当前存在的核心痛点（自然过渡到 1.2）
- **术语首次出现必须给出中文全称+英文缩写**（如"无线电能传输（Wireless Power Transfer, WPT）"）

#### 1.2 发明最接近的现有技术是什么？

撰写要求：
- 必须列出 **≥ 1 篇最接近的现有技术**（专利优先，含申请号/公开号 + 年份 + 简要方案描述）
- 如有 ≥ 2 篇，按相关度排序
- 明确指出该现有技术**解决了什么问题 / 采用了什么方案 / 达到了什么效果**
- 如果检索后发现"全球专利库中未检索到直接相关专利"，需明确说明并给出检索关键词
- 来源建议：EPO DOCDB/INPADOC（覆盖 100+ 国家）、Google Patents、Patentscope

---

### 二、现有技术的技术问题

撰写要求：
- 用 **编号列表（1)(2)(3)...）** 罗列现有技术的不足
- 每条以 **"缺乏..."** 或 **"未提供..."** 的句式开头（直接对应后续发明点）
- 与第一节 1.2 中的现有技术**一一对应**（不能凭空冒出未提过的现有技术）
- 每条技术问题应能映射到第三节的某个发明点（保持"问题—方案"对应关系）

---

### 三、技术方案的发明点概述

撰写要求：
- 一段总体描述 + 编号子项（1)(2)(3)...）
- 每个发明点用 **一句话核心主张** 开头，后接技术细节
- 软硬结合案件至少从**硬件结构**与**控制方法**两个维度阐述
- 区别于现有技术（明确"区别于现有 XXX 方案，本方法..."）
- 与第二节的"技术问题"**严格对应**：1 个问题 → ≥ 1 个发明点

---

### 四、技术方案的详细阐述

> **本节是交底书的核心，篇幅应占全文 60% 以上。**

撰写要求：
- **公开充分原则**：以"本领域技术人员能够实施"为标准，**把代理师当研发新人**
- **图文对应**：每张图都必须有对应的文字描述（**不能仅有图而无文字**）
- **公式编号**：所有公式用 `**【公式 N】**` 标注，便于代理师引用
- **附图编号**：所有附图用 `**【图 N】**` 标注，图题需完整
- **同一术语贯穿全文**：同一对象必须用同一个词（专利法"清楚"要求）

#### 4.X 硬件结构部分（软硬结合案件必备）

- 详细描述每个硬件组件（材料、尺寸、参数、连接关系）
- 每个组件对应附图编号（如"发射端O线圈：配置为平面螺旋线圈，外径 270mm，匝数 20 匝..."）
- 描述组件之间的物理关系（位置、堆叠、耦合方式等）

#### 4.Y 控制方法 / 算法部分（软硬结合案件必备）

- 用 **步骤一、步骤二、...** 编号清晰列出方法步骤
- 每个步骤描述：输入参数 → 处理逻辑 → 输出结果
- 涉及的公式必须编号并给出变量含义
- 算法参数（种群规模、迭代次数、阈值等）必须给具体数值

#### 4.Z 电路 / 拓扑结构（涉及电路案件必备）

- 完整描述电路连接关系
- 不同连接方式（如串联型 vs 并联型）分别画图并对比

**附图建议清单**（软硬结合案件典型）：
- 整体三维结构示意图
- 工作原理示意图（如磁场分布、信号流）
- 关键组件参数标注图
- 性能曲线图（如不同偏移下的互感/效率变化）
- 电路图（不同拓扑分别画图）
- 流程图（控制方法步骤）

---

### 五、第四项的技术手段产生了什么技术效果

撰写要求：
- 用 **编号列表（1)(2)(3)...）** 罗列技术效果
- 每条**严格对应第四节的一个技术手段**（效果 ← 手段）
- 效果描述需**可量化或可对比**（如"较传统 X 方案，Y 提升 Z%"）
- 不要只写"提升效率"等模糊表述，应写"全偏移范围平均传输效率较传统 O-to-O 磁耦合器显著提升"

---

### 六、第四项的技术方案中可以替代的地方（若无，可不填）

撰写要求：
- 列出可替代的实现方式（不同材料、不同参数、不同算法、不同拓扑等）
- 若无可替代方案，明确写"无"
- 此节帮助代理师**扩大权利要求的保护范围**（fallback 位置）

---

### 七、术语解释

撰写要求：
- **所有英文缩写必须给出英文全称和中文注释**
- **所有英文单词必须给出中文翻译或解释**
- 用表格形式呈现

| 术语/缩略语 | 解释说明 |
|------------|---------|
| WPT | Wireless Power Transfer，无线电能传输 |
| LCC-S | Inductance-Capacitance-Capacitance-Series，电感-电容-电容-串联补偿拓扑 |
| ... | ... |

---

### 八、参考文献

撰写要求：
- 列出对理解技术方案有帮助的**专利/论文/期刊**
- 每条包含：编号 + 公开号/出处 + 年份 + 简要说明
- 格式示例：
  - `[1] CN202511618329 (2026) — 具有抗偏移特性的双负载自动引导车无线充电系统。采用正交 DD 型磁耦合机构与 LCC-S 谐振补偿网络。`
  - `[2] CN110829615A (2020) — 一种应用于磁耦合无线充电传输系统的磁耦合机构位置自动对准方法。哈尔滨工业大学。`

## 质量自检清单（ACIP 交底书专属）

- [ ] 表头 7 个字段全部填写（案件名称 / 发明人 / 申请人 / 联系人 × 3 / 是否已公开发表）
- [ ] 第一节 1.2 列出 ≥ 1 篇最接近现有技术（含申请号+年份+方案描述）
- [ ] 第二节技术问题与第一节现有技术一一对应
- [ ] 第三节发明点与第二节技术问题一一对应
- [ ] 第四节占全文 ≥ 60% 篇幅，硬件结构与控制方法均详细阐述
- [ ] 每张图都有对应的文字描述（无"裸图"）
- [ ] 所有公式用 `【公式 N】` 编号
- [ ] 所有附图用 `【图 N】` 编号 + 完整图题
- [ ] 第五节技术效果与第四节技术手段一一对应，效果可量化
- [ ] 第六节明确说明可替代方案或"无"
- [ ] 第七节术语表完整（所有英文缩写都有全称+中文）
- [ ] 第八节参考文献格式规范
- [ ] 全文同一对象使用同一术语（无前后不一致）
- [ ] 提供可编辑附图原图（.vsd / .svg，由 patent-figforge 生成）

## 输出模式适配

disclosure 默认且唯一常规输出为 `.docx`（通过 `scripts/fill_acip_template.py fill` 填充 `assets/raw_templates/acip_invention_disclosure.docx`）。

- **`.docx`**（默认）
  - 文件名：`Disclosure-ACIP-[ShortTitle]-[YYYYMMDD].docx`
  - 附图：由 `patent-figforge` skill 生成 SVG/PNG，文末标注"正式提交需替换为 Visio (.vsd) 原图"
  - 公式：用 KaTeX（`$...$` 或 `$$...$$`）
- **`.md`**（仅作 `.docx` 生成失败的异常兜底，详见 `references/docx_mode.md` § 3）
  - 文件名：`Disclosure-ACIP-[ShortTitle]-[YYYYMMDD].md`（不加 `-generic-` 后缀）
