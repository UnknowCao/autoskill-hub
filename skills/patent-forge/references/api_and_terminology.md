# Patent Forge Reference

> **工具分层说明**：本文件记录 3 个**专利检索专用 API**（Optional 增强层），叠加在主搜索工具之上（详见 `shared_workflow.md` § Phase 2 **搜索工具分层**）。
> 主搜索工具按以下优先级探测：① `anysearch` skill（首选）→ ② `tavily` skill（次选）→ ③ `fetch_webpage` 内置工具（兜底，仅抓已知 URL）。
>
> **专利专用 API 优先级**（配置了对应 key 才启用，可叠加在任一主搜索层上）：
> 1. **CNIPA.AI**（`CNIPA_API_KEY`）— **首选**，以中国专利为中心，中英双语自动翻译匹配，对中国专利覆盖最佳
> 2. SerpAPI（`SERPAPI_KEY`）— Google Patents 关键词检索，全球专利覆盖
> 3. Exa.ai（`EXA_API_KEY`）— 语义检索，适合概念模糊场景
>
> 未配置任何 key → 跳过本文件以下三节，仅用主搜索工具分层检索。

## CNIPA.AI API（中国专利专用检索 — 首选 Optional 增强层）

> **来源**：https://cnipa.ai/zh/api-docs（2026-07-23 抓取）。CNIPA.AI 是独立第三方工具，与中国国家知识产权局（CNIPA）无关联；专利数据来源于公开数据库。

### 身份验证

所有请求需在 `Authorization` 头以 Bearer 令牌形式携带 API 密钥。在 https://cnipa.ai/register 创建账户获取。

### 检索端点（本 skill 仅使用以下 2 个检索端点）

```
GET https://api.cnipa.ai/v1/patents/search?q=<keywords>
GET https://api.cnipa.ai/v1/patents/:id
```

### Search 参数（query string）

| 参数 | 说明 | 示例 |
|------|------|------|
| `q` | 关键词（中英双语，系统自动翻译匹配）| `q=solid-state battery cathode material` |
| 申请人 | 申请人过滤（文档未暴露 query 参数名，优先用 `q` 传公司名）| `q=Huawei` / `q=BYD` |
| IPC 分类号 | 用 `q` 传 IPC 码配合关键词 | `q=H01M battery` / `q=G06F` |
| 公开日范围 | UI 支持，API 参数名未公开 | 若需精确日期过滤，回退 SerpAPI |

### Search 示例

```bash
curl -X GET "https://api.cnipa.ai/v1/patents/search?q=(solid-state%20battery)%20cathode%20material" \
  -H "Authorization: Bearer ${CNIPA_API_KEY}" \
  -H "Content-Type: application/json"
```

### 检索技巧（来自官方 Patent Search Guide）

- **双语检索**：可输入英文，系统自动翻译并匹配中文专利（如 `electric vehicle battery` 自动匹配中文电动汽车电池专利）
- **精确关键词**：`solid-state battery cathode material` 比 `battery` 更精确
- **组合检索**：用空格分隔多个关键词
- **IPC + 关键词组合**：如 `H01M battery` 提升准确度
- 专利类型过滤：发明 / 实用新型 / 外观设计

### Detail 端点

`GET /patents/:id` 通过 ID 获取专利详情（权利要求、说明书、法律状态等），用于 Step 2.6 新颖性分析中深入对比最接近现有技术。

### 本 skill 不使用的端点（红线声明）

CNIPA.AI 另有 2 个**撰写端点**（`POST /patent-writing/analyze`、`POST /patent-writing/generate-claims`），本 skill **明确禁用**：
- 权利要求撰写受 **Checkpoint 3A-claims + Anti-Pattern 红线**管控，必须由本 skill 按中国专利法实施细则规范自行撰写并经用户确认
- 外部 AI 生成的权利要求存在不支持说明书、用语不规范（专利法 26.4）的风险
- 详见 `anti_patterns.md` Anti-Pattern #19

### 故障处理

- HTTP 401/403 → key 无效或额度耗尽，告知用户检查 `CNIPA_API_KEY`，回退到 SerpAPI/Exa.ai 或主搜索分层
- 0 结果 → 用同义词/IPC 码重试一次 → 仍 0 结果则回退 SerpAPI/Exa.ai + 主搜索分层
- 429 限流 → 跳过 CNIPA.AI，审计日志记录状态

## SerpAPI Google Patents (Structured Search — Optional Enhancement Layer)

### Endpoint

```
GET https://serpapi.com/search.json?engine=google_patents
```

### Parameters

| Parameter | Required | Description |
|-----------|----------|-------------|
| `engine` | Yes | Must be `google_patents` |
| `api_key` | Yes | Your SerpAPI key |
| `q` | Yes | URL-encoded Boolean query |
| `num` | No | Results per page (10-100) |
| `sort` | No | `new` or `old` |
| `language` | No | `ENGLISH`, `CHINESE`, etc. |
| `status` | No | `GRANT` or `APPLICATION` |

### Query Syntax

```
(machine learning) AND (recommendation)
(AI) OR (artificial intelligence)
assignee:(Google)
inventor:(Smith)
```

### Response Structure

```json
{
  "organic_results": [
    {
      "publication_number": "US12345678B2",
      "title": "Patent Title",
      "snippet": "Description...",
      "priority_date": "2020-01-15",
      "assignee": "Tech Corp",
      "inventor": "John Smith"
    }
  ]
}
```

### Example

```bash
curl -s "https://serpapi.com/search.json?engine=google_patents&q=(machine%20learning)%20AND%20(recommendation)&api_key=KEY&num=20"
```

## Exa.ai Search API (Semantic Search)

### Endpoint

```
POST https://api.exa.ai/search
```

### Headers

| Header | Required | Value |
|--------|----------|-------|
| `x-api-key` | Yes | Your Exa.ai API key |
| `Content-Type` | Yes | `application/json` |

### Request Body

```json
{
  "query": "semantic description of the invention",
  "type": "neural",
  "numResults": 20,
  "includeDomains": ["patents.google.com", "patentscope.wipo.int", "espacenet.com"],
  "contents": {
    "text": true,
    "summary": true
  }
}
```

### Parameters

| Parameter | Type | Description |
|-----------|------|-------------|
| `query` | string | Natural language search query |
| `type` | enum | `neural` (semantic), `fast`, `auto`, `deep` |
| `numResults` | int | Results to return (max 100) |
| `includeDomains` | array | Restrict to specific domains |
| `excludeDomains` | array | Exclude domains |
| `category` | enum | `research paper`, `pdf`, `news`, etc. |
| `startPublishedDate` | string | ISO 8601 date filter |
| `contents.text` | bool | Include full text |
| `contents.summary` | bool | Include AI summary |

### Response Structure

```json
{
  "results": [
    {
      "title": "Patent Title",
      "url": "https://patents.google.com/patent/US12345678B2",
      "publishedDate": "2023-01-15",
      "summary": "AI-generated summary of the patent...",
      "text": "Full patent text content..."
    }
  ]
}
```

### Patent Domains

Use these in `includeDomains` for patent search:
- `patents.google.com` - Google Patents
- `patentscope.wipo.int` - WIPO PatentScope
- `espacenet.com` - European Patent Office
- `patents.justia.com` - Justia Patents

### Example Request

```bash
curl -X POST 'https://api.exa.ai/search' \
  -H 'x-api-key: YOUR_KEY' \
  -H 'Content-Type: application/json' \
  -d '{
    "query": "machine learning calendar scheduling focus time recommendation",
    "type": "neural",
    "numResults": 10,
    "includeDomains": ["patents.google.com"],
    "contents": {"summary": true}
  }'
```

## Language Conventions

> **目的**：本节是 patent-forge 撰写中英文专利文档时的**语言规范单一事实源**。所有规范对齐中国《专利法》第 26 条（公开充分 + 权利要求清楚/支持）、实施细则第 22-23 条、以及《专利审查指南 2023》第二部分第二章。SKILL.md `references/api_and_terminology.md` 链接指向本节；质量清单 A/D（`quality_checklists.md`）的"语言合规"项交叉引用本节。
>
> **写作风格（对 AI 最有效）**：每条规则配 **❌ 错误 → ✅ 正确** 对照；关键规则标注**法条锚点**（如 `[专利法 26.4]`）让 AI 知道违反后果；判定用**决策条件**而非散文。

### 1. 词汇级规范（禁用词 + 替代词）

#### 1.1 权利要求书绝对禁用词（命中即驳回 `[专利法 26.4]`）

权利要求必须用**确定性语言**。下列词出现在权利要求中 → 审查员以"权利要求不清楚"驳回。

| 类别 | ❌ 禁用词（中文 / 英文）| ✅ 替代写法 |
|------|--------------------|-----------|
| 模糊范围限定 | 优选地 / 优选的 / 较佳地 / 优选 | 删除该词，把优选范围写入**从属权利要求**（如"根据权利要求 1 所述的 X，其特征在于，所述 Y 的取值范围为 a-b"）|
| 不确定数量 | 大约 / 约 / 大概 / 左右 / approximately / about / around / substantially | 给出**具体数值或数值范围**：`5V±0.1V` / `4.9V-5.1V` / `≥100MΩ`。如必须留容差，用"±"或区间表达 |
| 主观判断 | 良好 / 良佳 / 优秀 / 高效 / 快速 / 稳定 / 高质量 / good / efficient / stable / fast / robust / sufficient / adequate | 量化为**可测阈值**：`信噪比 ≥ 30dB` / `响应时间 ≤ 100ms` / `失效率 ≤ 1×10⁻⁶` |
| 模糊程度 | 适当 / 合适 / 必要 / 基本 / 大致 / 充分 / appropriate / suitable / necessary / substantially | 删除或量化：`温度维持在 25°C±2°C`（不要"适当温度"）|
| 功能性结果 | 使得...更好 / 从而提高效率 / 以改善性能 | 改为**结构/步骤限定**："所述散热片(40)的表面积 ≥ X cm²，使得工作时结温 ≤ Y°C"（用结构推出效果，不直接声明效果）|
| 商业宣传 | 革命性 / 突破性 / 业界领先 / 世界首创 / revolutionary / leading | 删除——专利文档禁止商业宣传语 |

#### 1.2 说明书中允许但需克制的词

说明书比权利要求宽松（允许"优选地""大约"等），但仍需克制：

| 场景 | 说明书中允许 | 风险 / 克制原则 |
|------|------------|---------------|
| 优选实施方式 | "在一种优选实施方式中..." | ✅ 允许，但**优选的具体参数必须同时落入权利要求范围**，否则构成"说明书不支持权利要求" `[专利法 26.4]` |
| 大致数值 | "电压大约为 5V" | ⚠️ 允许，但**关键参数必须给精确值或范围**（实施例中应给 5.0V、5.1V 等具体点）|
| 主观效果描述 | "本发明显著提升了传输效率" | ⚠️ 允许作为技术效果陈述，但**必须有量化对比数据支撑**（第五节技术效果需附"较现有技术提升 X%"）|

#### 1.3 产品名 / 品牌名 / UI 术语禁用（通用化）

| ❌ 禁用 | ✅ 通用化替代 |
|--------|------------|
| iPhone / MacBook / Galaxy / 华为手机 | 移动终端设备 / 便携式计算设备 / 用户设备 |
| 按钮 / 页面 / 弹窗 / 下拉框 / 输入框 / 复选框 | 用户交互元素 / 显示界面 / 输入组件 / 选择控件 / 图形用户界面（GUI）|
| Google 搜索 / 微信 / 支付宝 / Excel | 网络搜索引擎 / 即时通信应用 / 电子支付应用 / 电子表格应用 |
| Wi-Fi / Bluetooth / 5G（作为产品名时）| 无线局域网（WLAN）/ 短距离无线通信 / 移动通信网络（**作为技术标准引用时可保留并给全称**，如"符合 IEEE 802.11 标准的无线局域网"）|
| iOS / Android / Windows / Linux | 操作系统 / 移动操作系统 / 桌面操作系统 |
| USB / Type-C（作为产品名时）| 通用串行总线接口 / 标准 Type-C 接口（**首次出现给全称**：通用串行总线（Universal Serial Bus, USB））|

#### 1.4 口语化连接词（专利表述替换）

| ❌ 口语 | ✅ 专利表述 |
|--------|----------|
| 然后 / 接着 / 之后 | 随后 / 进而 / 继而 |
| 如果...就... | 响应于...，执行... / 当...时，... |
| 因为...所以... | 由于...，因此... / 基于...，确定... |
| 为了 / 目的是 | 用于 / 配置为 / 用以 |
| 把 A 给 B | 将所述 A 传输至所述 B / 将所述 A 提供给所述 B |
| 通过 X 来做 Y | 通过所述 X 实现 Y / 借助于所述 X 执行 Y |
| 是一个 / 是一种 | 包括 / 包含 / 由...组成 / 具有 |

### 2. Standard Phrases（标准句式）

#### 2.1 发明名称 / 摘要开头

| 用途 | 句式 | 示例 |
|------|------|------|
| 发明名称 | `一种[应用领域]的[核心装置/方法]` | 一种用于电池管理系统的荷电状态估算方法 |
| 摘要开头 | `本发明涉及[技术领域]，特别涉及一种[核心方案]。` | 本发明涉及电池管理技术领域，特别涉及一种基于大语言模型的验证标准生成方法。 |
| 独立权利要求前序 | `一种[装置/方法/系统]，包括[已知技术特征]，` | 一种电池管理系统，包括电压采集单元(10)和主控单元(20)， |

#### 2.2 权利要求关键句式

| 用途 | 句式 | 注意事项 |
|------|------|---------|
| 区别特征引出 | `其特征在于：[区别技术特征]` | 二段式"前序部分 + 其特征在于"为中国专利法实施细则第 22 条强制要求 |
| 从属权利要求引用 | `根据权利要求 [N] 所述的 [前序主题]，其特征在于：[附加技术特征]` | N 必须 < 当前权利要求编号；前序主题必须与被引用权利要求一致 |
| 指代前文元素 | `所述 [术语]([参考标号])` | 首次出现给参考标号；之后用"所述"+相同术语；同一对象严禁同义词混用（如"处理器"和"控制单元"指同一物）|
| 功能限定 | `配置为[功能]的[模块]` / `用于[功能]的[装置]` | 功能限定需说明书支持（说明书中必须有对应的结构/步骤实现）`[专利法 26.4]` |
| 范围限定 | `[参数]为[数值范围]` / `[参数]满足[关系式]` | 用 `≥ ≤ =` 或 `X-Y` 区间；**禁止** "大约/优选" |
| 方法步骤 | `步骤一，[动作]；步骤二，[动作]；...` | 每步骤必须有明确输入/输出；步骤顺序若重要须显式编号 |
| 闭环引用 | `根据[条件]，确定[结果]` / `响应于[事件]，执行[动作]` | 因果关系明确，不留歧义 |

#### 2.3 说明书过渡句式

| 用途 | 句式 |
|------|------|
| 引出实施例 | `图 N 示出了本发明一种[实施方式]的[结构/流程]示意图。` / `下面结合附图对本发明的[实施方式]进行详细说明。` |
| 公式引出 | `所述[步骤]可通过以下公式计算：【公式 N】 [公式]`，其中 [变量] 为 [含义] |
| 数值引出 | `在一种实施方式中，所述[参数]的取值范围为 [X-Y]，优选为 [Z]。`（说明书中"优选"允许）|
| 替代方案引出 | `可替代地，所述[组件]也可以[另一实现方式]。` / `在另一实施方式中，...` |
| 技术效果引出 | `通过上述[技术手段]，本发明实现了[技术效果]，较[现有技术]提升/降低 [量化值]。` |

### 3. 5 大章节语言规范（按文档部分）

#### 3.1 权利要求书（最严格）

| 规则 | 要求 | 法条 |
|------|------|------|
| 二段式 | 每条独立权利要求必须为"前序部分（已知技术）+ 其特征在于（区别技术）"二段式 | 实施细则 22 条 |
| 清楚 | 每个限定词必须确定；禁用 1.1 表中所有模糊词 | 专利法 26.4 |
| 支持 | 每个特征必须在说明书中有对应公开（结构/步骤/参数）| 专利法 26.4 |
| 简洁 | 一条权利要求一个独立技术方案；不写非必要限定 | 审查指南 二部分二章 3.2 |
| 引用基础 | 从属权利要求引用的"所述 X"必须在被引用权利要求中已定义 | 实施细则 22 条 |
| 参考标号 | 权利要求中**可加可不加**参考标号；加了须与说明书/附图一致（中国实务：通常说明书必加，权利要求可不加）| 审查指南 二部分二章 3.3 |

❌ `1. 一种电池管理系统，包括处理器，其特征在于：所述处理器配置为高效地估算电池状态。`
✅ `1. 一种电池管理系统，包括电压采集单元(10)和主控单元(20)，其特征在于：所述主控单元(20)配置为根据所述电压采集单元(10)采集的电压信号，按照【公式 1】计算电池的荷电状态，所述荷电状态的计算精度 ≤ ±5%。`

#### 3.2 说明书（充分公开 `[专利法 26.3]`）

| 规则 | 要求 |
|------|------|
| 公开充分 | "本领域技术人员能够实施"为标准——把代理师当研发新人，给可实施细节（材料/尺寸/参数/步骤/公式）|
| 图文对应 | 每张附图必须有对应文字描述（禁止"裸图"）|
| 公式编号 | 所有公式用 `**【公式 N】**` 标注 |
| 附图编号 | 所有附图用 `**【图 N】**` 标注 + 完整图题 |
| 实施例数量 | ≥ 3 个可区分实施例（不同维度变化），覆盖优选 + 替代实现 |
| 参数范围 | 关键参数给**范围 + 实施点**（如"温度为 -40°C~+85°C，实施例 1 取 25°C，实施例 2 取 -40°C"）|

#### 3.3 摘要（最简短）

| 规则 | 要求 | 法条 |
|------|------|------|
| 字数 | ≤ 300 字（中文）/ ≤ 150 words（英文）| 实施细则 23 条 |
| 段落 | **单段**，不分段 | 实施细则 23 条 |
| 内容 | 仅发明名称 + 所属技术领域 + 解决的技术问题 + 技术方案要点 + 主要用途 | 审查指南 二部分二章 2.3 |
| 禁止 | **不得**引用权利要求编号（如"如权利要求 1 所述"）| 实施细则 23 条 |
| 禁止 | **不得**含商业宣传语 | 审查指南 |
| 摘要附图 | 指明 1 幅最有代表性的附图（如"摘要附图：图 1"）| 实施细则 23 条 |

❌ `本发明涉及如权利要求 1 所述的一种电池管理系统...` （引用了权利要求编号）

### 5. 法条驳回依据映射（违反 → 驳回）

> 撰写时自检：每条规则对应一个法条，违反即构成驳回依据。AI 在 Checkpoint 4A/4D 时按此表反向核对。

| 法条 | 内容 | 典型违反 | 修复方向 |
|------|------|---------|---------|
| 专利法 26.3 | 说明书应当清楚、完整地公开发明 | 说明书缺关键参数/步骤，本领域技术人员无法实施 | 补充实施细节至"可实施"标准；**禁止编造**（Anti-Pattern #17）|
| 专利法 26.4 | 权利要求应当清楚、简明，并得到说明书支持 | 权利要求含模糊词（大约/优选）；权利要求特征在说明书中无对应公开 | 删模糊词；补说明书支持；或缩减权利要求范围 |
| 实施细则 22 条 | 权利要求应包括前序部分和特征部分；从属权利要求引用基础正确 | 独立权利要求无"其特征在于"；从属权利要求引用未定义的"所述 X" | 改为二段式；补引用基础 |
| 实施细则 23 条 | 摘要 ≤300 字单段、不含权利要求编号、附摘要附图 | 摘要分段、引用"如权利要求 1 所述"、超 300 字 | 改单段、删引用、精简至 ≤300 字 |
| 审查指南 二部分二章 3.2 | 权利要求应当简要 | 一条权利要求堆砌非必要限定（保护范围过窄）| 拆分为多条从属权利要求 |
| 审查指南 二部分二章 3.3 | 权利要求中的参考标号不限定保护范围 | 误把参考标号当作限定（如"所述处理器(20)"被理解为限定了型号）| 参考标号仅用于指代，不构成限定 |
| 审查指南 二部分二章 2.2.3 | 背景技术应客观陈述 | 抹黑现有技术、泄露本发明方案 | 改为客观陈述，把方案移至发明内容 |
